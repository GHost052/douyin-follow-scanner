# 产品规格说明（PRD）

> 项目：**抖音关注清理助手 / douyin-follow-cleaner**
> 版本：v0.1 草案
> 日期：2026-10-02
> 状态：待确认

---

## 1. 要解决的问题

### 1.1 核心痛点

抖音的关注列表**没有"按最后更新时间排序/筛选"的能力**。当关注数达到几百甚至上万时：

- 想清理一批"已经不更新"的账号，只能一个个点进主页看最新作品日期 —— **上万个账号，人工完全不现实**
- 关注列表质量持续劣化，信息流里充斥停更号
- 没有任何工具能告诉你"你关注的哪些人已经很久没发作品了"

### 1.2 一句话定位

> 一个**轻量桌面小工具**：一键扫描你的抖音关注列表，找出其中**超过 N 天没有更新**的账号，并导出清单供你手动清理。

### 1.3 目标用户

| 优先级 | 用户群 | 特征 | 核心诉求 |
|---|---|---|---|
| P0 | **重度抖音用户** | 关注数 500~10000+，有"关注洁癖" | 快速找出停更号，做一次清理 |
| P1 | **内容运营 / 自媒体** | 需要维护关注列表以跟踪同行动态 | 定期巡检，识别"掉队"的账号 |
| P2 | 开源社区开发者 | 想自建、二次开发 | 代码可读、可扩展、可自部署 |

**用户画像（典型）**：非技术背景，希望**双击就能用**；不愿看命令行，也不想配环境。

### 1.4 明确不做（Out of Scope）

- ❌ **批量取关**（已确认不做）—— 只输出清单，取关由用户在抖音 App 内手动完成，避免误操作与账号风险
- ❌ 云端 / 多用户 / 账号体系
- ❌ 移动端 App
- ❌ 内容分析、涨粉分析、推荐等扩展能力

## 2. 核心功能

### 2.1 功能清单（MVP）

| # | 功能 | 说明 | 优先级 |
|---|---|---|---|
| F1 | **扫码登录** | 首次使用扫码登录抖音，登录态本地保存，之后免登录 | P0 |
| F2 | **一键扫描** | 自动拉取全部关注账号，逐个查询最后更新时间 | P0 |
| F3 | **进度可视化** | 实时显示进度、当前账号、预计剩余时间，可暂停/继续 | P0 |
| F4 | **结果查看** | 分类展示：停更 / 异常 / 正常；支持搜索、排序、筛选 | P0 |
| F5 | **导出清单** | 导出 CSV（可直接用 Excel 打开）+ 一键复制清单 | P0 |
| F6 | **增量扫描** | 再次扫描时只查"新增关注"和"已超期"的账号，不重复劳动 | P0 |
| F7 | **断点续传** | 中断后重新打开可继续，不丢失已完成的进度 | P0 |
| F8 | **风控保护** | 内置限速 + 预防性休息 + 重试上限，尽量降低被拦截概率 | P0 |
| F9 | **设置** | 阈值天数（默认 60）、速度档位、数据目录 | P1 |
| F10 | **可视化报告** | 生成 HTML 报告，含统计与清单表格 | P1 |
| F11 | **扫描历史** | 记录每次扫描的时间与结果，可对比"新增停更" | P2 |

### 2.2 关键设计原则

1. **默认安全**：默认速度档为"保守"，宁可慢也不触发风控
2. **可中断**：任何时刻关闭都不丢数据，下次继续
3. **零配置可用**：装好双击就能跑，高级选项藏在设置里
4. **数据本地**：所有数据（登录态、数据库、报告）只存在本机，不上传任何服务器

## 3. 主要操作流程

### 3.1 首次使用（向导式）

```
启动应用
  → 欢迎页：一句话说明 + 免责声明勾选
  → 点击「登录抖音」→ 弹出浏览器窗口扫码
  → 登录成功，自动读取关注总数
  → 设置阈值天数（默认 60 天）
  → 点击「开始扫描」
  → 进度页（可最小化，后台继续）
  → 扫描完成 → 结果清单自动刷新在下方
  → 导出清单 / 复制
```

### 3.2 日常使用（一键）

```
启动应用
  → 主页显示上次扫描摘要（关注总数 / 停更数 / 上次扫描时间）
  → 点击「开始扫描」（自动增量，通常几分钟）
  → 查看结果清单 → 导出
```

### 3.3 异常分支

| 情况 | 应用行为 |
|---|---|
| 登录态失效 | 提示"登录已过期"，引导重新扫码 |
| 触发风控 | 显示"正在等待风控解除"，倒计时；重试 3 次仍失败则停止并提示稍后再试 |
| 用户关闭扫描窗口 | 立即暂停，进度已保存，下次继续 |
| 未安装 Edge/Chrome | 引导安装或提示使用内置浏览器模式 |
| 账号无公开作品 / 私密 | 归入"异常账号"，在结果清单里单列 |

## 4. 页面与模块

### 4.1 页面清单（极简：2 个页面）

| 页面 | 职责 | 关键元素 |
|---|---|---|
| **① 主页 Main** | 概览 + 扫描 + 结果（合一页） | 顶部 3 个统计数字（关注总数 / 停更 / 正常）；「开始扫描」「登录抖音」；扫描中在下方展开进度条、当前账号、速度、剩余时间、暂停/停止；再往下是 Tab（停更 / 异常 / 全部）+ 搜索框 + 表格 + 导出按钮；底部可折叠运行日志 |
| **② 设置 Settings** | 配置与信息 | 阈值天数、速度档位、数据目录、免责声明、清空数据 |

> 设计变更（v0.2）：原本规划的「首页 / 扫描页 / 结果页 / 设置页」4 个页面，合并为「主页 / 设置」2 个页面。理由：三者本质是同一条主流程的不同阶段（看概览 → 点扫描 → 看结果），合并后无需来回切换，更符合极简原则。

### 4.2 模块划分（技术视角）

```
┌─────────────────────────────────────────────┐
│  界面层（极简 HTML/CSS/JS，无重框架）          │

                   │ 本地 HTTP（127.0.0.1）
┌──────────────────▼──────────────────────────┐
│  服务层  server.js                           │
│  /  页面    /api/progress  进度             │
│  /report 报告    /api/export  导出           │
└──────────────────┬──────────────────────────┘
                   │
┌──────────────────▼──────────────────────────┐
│  业务层                                      │
│  scanner  扫描编排（增量 / 续传 / 限速）       │
```

### 4.3 数据表

**accounts**

| 字段 | 类型 | 说明 |
|---|---|---|

| uid | TEXT | 数字 ID |
| nickname | TEXT | 账号名 |
| home_url | TEXT | 主页链接 |
| avatar | TEXT | 头像 |
| aweme_count | INTEGER | 作品数 |
| last_update_ts / last_update_date | INTEGER / TEXT | 最后更新时间 |

**runs**：每次扫描的 started_at / finished_at / queue / checked / stale / active / err

## 8. 支持平台

| 平台 | 支持 | 说明 |
|---|---|---|
| **Windows 10/11 (x64)** | ✅ 主目标 | 一键启动器 + 可选单文件 exe |
| **macOS 11+ (Intel/Apple Silicon)** | ✅ | `.command` 启动器 / `.app` |
| **Linux (x64)** | ✅ | `.desktop` 启动器 |
| **移动端 (iOS / Android)** | ❌ 不支持 | 技术限制，见下 |
| 浏览器 | 依赖系统已装 Edge / Chrome | 无则引导安装或使用内置 Chromium 模式 |

**为什么不做移动端**：扫码登录需要另一个设备、浏览器自动化无法在移动端运行、长时间后台扫描会被系统杀死。

## 9. 技术限制与约束

| # | 限制 | 影响 | 应对 |
|---|---|---|---|
| L1 | **必须本地运行** | 无法做成云端多用户服务 | 定位为本地桌面工具 |
| L2 | **浏览器无法完全去掉**（已实测，见 `docs/browser-dependency.md`） | ① 登录需浏览器扫码；② 作品接口强制校验 `a_bogus` 签名，Node 端无法生成 | 采用**后台 headless 浏览器**：用户全程看不到窗口，且复用系统浏览器、不增加打包体积 |
| L3 | **风控**：约每 1000~1500 次请求触发一次接口拦截，约 1 小时恢复 | 全量扫描 9000+ 账号需数小时 | 限速 + 预防性休息 + 重试上限 3 次 + 断点续传 |
| L4 | 关注列表接口每页仅约 22 条 | 9000 账号需约 445 次请求 | 支持缓存与断点续传 |
| L5 | 接口无"最后更新时间"字段 | 必须逐账号查询作品 | 单账号仅需 1 次请求，取最近作品 `create_time` |
| L6 | 依赖 Node 内置 `node:sqlite` | 需 Node ≥ 22.13 | 打包时内置运行时 |
| L7 | 可能违反抖音用户协议 | 法律与账号风险 | 显著免责声明 + 默认保守速度 + 不提供取关 |
| L8 | 打包体积 | Electron 含 Chromium 约 150MB+ | 采用**轻量方案**：复用系统浏览器，外壳极小 |

## 10. 技术方案（轻量桌面应用）

**核心思路：复用系统浏览器，不打包 Chromium。**

```
┌────────────────────────────────────────────┐
│  启动器（极小，< 1MB）                       │
│  启动本地 Node 服务 → 用系统浏览器 App 模式   │
│  打开无边框窗口：msedge --app=http://127.0.0.1:8799 │
└────────────────────────────────────────────┘
```

- **界面**：纯 HTML/CSS/JS，无前端框架（保持极简与轻量）
- **后端**：Node.js（复用现有 `src/` 代码，重构为 scanner / db / report / server）
- **浏览器**：用**原生 CDP**（Chrome DevTools Protocol，零依赖）以 **headless（无窗口）** 模式驱动系统 Edge/Chrome，**不下载 Chromium**；用户全程看不到浏览器窗口。仅首次登录需弹窗扫码一次（详见 `docs/browser-dependency.md`）
- **数据**：SQLite（`node:sqlite`），单文件

**打包演进路线**

| 阶段 | 方案 | 体积 | 用户体验 |
|---|---|---|---|
| **M2** | 启动器脚本（`.bat` / `.command` / `.desktop`）+ 说明 | ≈ 0 | 双击启动，浏览器 App 窗口 |
| **M3** | Node SEA + 自研零依赖打包器 | ~83MB（含 Node 运行时） | 双击 exe，无需装 Node | ✅ 已完成
| **M4** | Tauri / Neutralino 外壳 + Node sidecar | 外壳 5~10MB | 真原生窗口，体验最佳 |

> 推荐路径：**先交付 M2（立刻可用），再逐步做到 M3 / M4。**

### M2 验收标准

1. 双击启动器，弹出应用窗口（非普通浏览器标签页感）
2. 首次使用：扫码 → 设置阈值 → 开始扫描，全程无需命令行
3. 扫描中显示实时进度，可暂停/继续，可关闭窗口后重开继续
4. 结果清单可按"停更/异常/全部"筛选，可搜索，可一键导出 CSV
5. 再次启动自动增量扫描，耗时显著短于首次
6. 所有数据仅存本地，无任何网络上传
